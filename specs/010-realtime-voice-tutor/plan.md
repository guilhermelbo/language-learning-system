# Implementation Plan: Real-Time Voice Tutor Conversation

**Branch**: `010-realtime-voice-tutor` | **Date**: 2026-06-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/010-realtime-voice-tutor/spec.md`

## Summary

Transform the Voice Tutor mode from a push-to-talk interaction into a hands-free, continuous conversation loop. The user speaks, silence is detected automatically, audio is sent to the backend, and the tutor's response streams back sentence-by-sentence (text + audio) without the user pressing any button. The core loop: mic active → silence detected → audio sent → SSE stream with progressive text + per-sentence audio → mic re-activated.

## Technical Context

**Language/Version**: Python 3.10+ (backend), TypeScript/Next.js 14 (frontend)

**Primary Dependencies**:
- Backend: FastAPI, httpx, `sse-starlette` (new), existing `llm_voice_service.py`
- Frontend: Web Audio API (native browser), `MediaRecorder` (native browser), React hooks

**Storage**: In-memory only (unchanged — `InMemoryOmniSessionRepository`)

**Testing**: pytest (backend), manual browser testing (frontend VAD)

**Target Platform**: Linux Docker container (backend), modern browser Chrome/Firefox desktop (frontend)

**Performance Goals**:
- First text token visible ≤ 2s from silence threshold
- First sentence audio playing ≤ 4s from silence threshold
- Mic re-enabled ≤ 500ms after audio queue drains

**Constraints**:
- No new infrastructure (no Redis, no WebSocket server, no new containers)
- `sse-starlette` is the only new backend dependency
- VAD must work with zero frontend npm packages added
- Existing non-streaming endpoint `POST /conversation/omni/speech` must remain unchanged

**Scale/Scope**: Single user per session (in-memory, no concurrent session conflicts)

## Key Implementation Decisions

### 1. Streaming via SSE (not WebSocket)
`EventSourceResponse` from `sse-starlette` on a `POST` endpoint. Unidirectional, HTTP/1.1 compatible, simpler than WebSocket. See [research.md](research.md#decision-2).

### 2. LLM Streaming via httpx `client.stream()`
Add `"stream": True` to the existing llamacpp payload in `_call_llm_stream`. Consume `data: {...}` lines from llamacpp, extract `delta.content` tokens. Uses existing `httpx` dependency. See [research.md](research.md#decision-3).

### 3. Sentence Boundary Detection via Regex Buffer
Accumulate tokens in a string buffer; split on `[.!?…]` followed by whitespace or end-of-stream. Each complete sentence is dispatched to Piper TTS immediately. See [research.md](research.md#decision-4).

### 4. Parallel TTS per Sentence
Each sentence is synthesized via `_synthesize()` (existing method) as soon as its boundary is detected. Results are yielded as `sentence_audio` SSE events in order. The backend does NOT wait for all sentences before starting TTS — each sentence is TTS'd and yielded as it completes.

### 5. VAD via Web Audio API AnalyserNode
No npm packages. `AnalyserNode.getByteFrequencyData()` every 100ms. RMS < 30/255 = silence. After `silenceThresholdMs` of silence following `minSpeechMs` of speech, emit blob. See [research.md](research.md#decision-1) and [contracts/frontend-vad-contract.md](contracts/frontend-vad-contract.md).

### 6. Audio Queue via Web Audio API
Received `sentence_audio` base64 WAV → `AudioBuffer` → `AudioBufferSourceNode` queue. Sentences play sequentially via `onended` chaining. Mic muted during playback. Re-enabled on `done` event + empty queue.

### 7. Non-Streaming Endpoint Unchanged
`POST /conversation/omni/speech` is NOT modified. Streaming is additive via a new endpoint.

## Risk Notes

- **llamacpp streaming with input_audio**: `stream: true` with multimodal `input_audio` content type should work (it's part of the OpenAI-compatible API spec), but must be verified in integration testing. If streaming is not supported with `input_audio`, fallback: collect full response first, then stream sentences to frontend.
- **Browser AudioWorklet**: Not supported in Safari < 14.5. For this iteration, target Chrome/Firefox desktop only (noted in spec assumptions).
- **Sentence splitting on abbreviations**: "Dr. Smith" would incorrectly split. Acceptable edge case for v1; NLTK can be added later.
